# Security and quality audit — 2026-09-29

Scope: `src/` (FastAPI backend), `frontend/`, `convex-adapter/`, docs, tooling, and CI.

Baseline before: `bun run verify` green — 472 passed, 1 skipped, 0 failed.
Baseline after: `bun run verify` green (exit 0) — 472 passed, 1 skipped, 0 failed.

`AGENTS.md` gates auth/bootstrap flows, session-pruning and trace-retention semantics, and
the Convex adapter contract. Findings in those areas are recorded, not changed.

## Fixed

### 1. Path traversal to arbitrary file write, then knowledge-base poisoning — High

`src/agents/cost_tracker.py` built a filename from a client-supplied `conversation_id`
(`src/app/dto.py`, max_length 120, no charset restriction) and opened it for writing. On
Windows an absolute value makes `Path.__truediv__` discard `data_dir` entirely; on POSIX
`../` escapes it. `src/agents/knowledge.py` then loads matching JSON back as a knowledge
document, so planted content is later treated as trusted knowledge by the assistant.
Reachable through `POST /api/v1/chat`.

Added `validate_conversation_id` (charset `[A-Za-z0-9_.-]{1,120}`, plus a requirement for at
least one alphanumeric so `.` and `..` are refused) and `_conversation_path`, which also
asserts the resolved parent equals `data_dir.resolve()` to catch cross-drive values such as
`D:evil`. `:` was deliberately excluded from the charset because Windows treats it as an
NTFS alternate-data-stream separator.

### 2. CSRF protection did not cover the cookie-authenticated web routes — High

`src/main.py` applied CSRF validation only to paths starting with `/api/`. `/chat`, `/login`
and `/logout` are cookie-authenticated, outside `/api/`, and completely unprotected, so a
cross-site form POST to `/chat` ran the whole pipeline (LLM spend, trace writes, file
writes).

These three routes are the server-rendered Jinja fallback forms — verified that no template
under `src/interface/templates/` renders any csrf token, and the React SPA only ever calls
`/api/v1/*`. A header-only check would therefore have made the fallback UI impossible to log
into. They are now guarded by `_csrf_origin_allowed`: a valid `X-CSRF-Token` is still
compared in constant time, otherwise the request must carry an `Origin`/`Referer` whose
netloc matches the request host. `/api/*` behaviour is unchanged.

### 3. Log injection — Medium

Client-supplied `user_id`, `username`, and `X-Request-ID` reached the log stream without
character restrictions, allowing forged log lines and terminal escape injection. The
`auth.py` sites were reachable unauthenticated. `X-Request-ID` was additionally echoed into
a response header.

Added `src/app/log_sanitize.py` (`sanitize_log_value`), which strips ANSI escapes before
control characters — the reverse order would leave the sequence body as inert-looking text —
then bounds the length. Applied in `enhanced_orchestrator.py`, `auth.py`, and `main.py`.

### 4. Internal error text disclosed to agent API callers — Medium

`src/app/automation.py` returned `str(exc)` in 500 responses, leaking internal paths, SQL and
library internals. It also persisted that text into the job payload, which `jobs.get` and
`jobs.list` re-served, so fixing only the response would have left the leak alive. Now logs
the detail with the request id and returns a generic message; status code, title, and
response shape are unchanged.

### 5. Documented commands that cannot work — High (user experience)

The documented first-run path was broken in several places, all verified against the real
manifests:

- `README.md` told users to run `pnpm docs:build` / `pnpm docs:check` in a Bun-only repo
  with no pnpm anywhere.
- `README.md` documented `bun run test` and `bun run build`; **neither script exists** in any
  manifest. Replaced with `python -m pytest -q` and `bun run build:js`, and the absence is
  now stated explicitly rather than implied.
- `CONTRIBUTING.md` used `npm install` / `npm run build`, contradicting both `README.md` and
  ADR `adr-0003`.
- `AGENTS.md` documented `pip install -e .`, but the repo has no `pyproject.toml` or
  `setup.py`, so the command cannot succeed.
- `README.md` contained `cd ..\convex-adapter` in a bash block, and three duplicated
  `## Documentation` headings.
- Also found and fixed while verifying: `python -m src.cli sync --limit 100` cannot parse —
  `--limit` is a root-parser option and `sync` takes no subparser arguments. The correct
  form is `python -m src.cli --limit 100 sync`.

### 6. A shipped default password in a copy-pasteable command — Medium

`README.md` showed `bootstrap-admin --password "change-this-password"`, contradicting
`AGENTS.md` ("no public default credentials, ever") and `SECURITY.md`. Replaced with a
placeholder and an explicit instruction to choose a strong secret. CLI syntax was verified
against `src/cli/__main__.py`.

### 7. `.tool-versions` violated the declared engine — Medium

All three `.tool-versions` files pinned `bun 1.2.19` against `packageManager: bun@1.3.14`,
`engines.bun: ">=1.3.14"`, and CI's `1.3.14`. asdf/hermit users got a Bun below the
declared minimum. All three now pin `1.3.14`.

### 8. `.npmrc` disabled both safety nets — Medium

`frontend/.npmrc` and `convex-adapter/.npmrc` both set `audit=false` and
`engine-strict=false`, making `engines` decorative and suppressing install-time CVE
reporting. Now `audit=true` and `engine-strict=true`. Enabling engine-strict was proven safe
by scanning all 124 installed packages: every `engines.node` range admits Node 24.

### 9. `convex-adapter` was never linted or format-checked — Medium

Root `lint` and `format:check` filtered only `supportoid-frontend`, so adapter formatting
regressions shipped green. Root `format:check` now also gates the adapter. This immediately
surfaced three previously unformatted files (`src/index.ts`, `README.md`, `tsconfig.json`),
which were then formatted; the change to `index.ts` is purely quote style, verified with
`git diff -w` (33/33 lines, no logic change).

### 10. `docs:build` silently did nothing while claiming success — Medium

`scripts/docs.mjs` never read `process.argv`, so the `build` argument was discarded and only
the check logic ran, printing "Documentation check passed". This mattered because
`docs:check` validates that each `docs/current/*.json` carries a `sourceChecksum` matching its
markdown — so editing any canonical doc breaks the check and the documented remedy could not
repair it. `docs.mjs` now dispatches on the argument: `check` behaves exactly as before,
while `build` exits non-zero with an explicit message that no generator is implemented,
instead of reporting a false success. The dead `docs/build-docs.mjs` stub was removed after
confirming nothing referenced it.

## Recorded, not changed — gated by AGENTS.md

- **`convex-adapter/src/index.ts` serves unauthenticated by default.** `API_KEY` defaults to
  `""`, and when unset `requireKey` calls `next()` unconditionally, so `/sync/event` and
  `/data/traces` are open with no startup warning. Line 51 also compares the key with `!==`,
  a timing side-channel. This is the adapter bridge contract — gated.
- **No login rate limiting ceiling.** `LoginRateLimiter._attempts` is keyed by
  attacker-supplied username with no global cap, so unauthenticated `POST
  /api/v1/auth/login` grows memory. Auth area — gated.
- **Pluggable plaintext password fallback.** `src/app/auth.py` (~308-310) compares `plain ==
  stored` when bcrypt is installed but the stored value is not a bcrypt hash, so a plaintext
  row stays a valid credential until that user logs in once. Auth flow — gated.
- **Rate limits keyed by client-supplied `user_id`, never pruned**
  (`src/agents/security_layer.py`) — defeated by rotating `user_id`, and unbounded. Pruning
  semantics — gated.
- **Session locks leak.** `enhanced_orchestrator.py` never deletes `_session_locks` entries;
  `prune_stale_sessions` removes only `original.sessions`. Pruning — gated.
- **Unbounded `audit_events`, `automation_jobs`, `approvals`.** `automation_store.py` prunes
  only `sessions`, while `record_audit_event` fires on every invoke and every approval.
  Retention — gated.
- **Unauthenticated amplification.** `GET /api/v1/health` triggers an outbound HTTP request
  plus a full session sweep per call.
- **Prompt injection.** `support_response.py` interpolates a raw Python `dict` repr
  containing untrusted ticket text into the prompt with no delimiter; a `}` breaks out.
  `ResponseValidator` limits the damage to bad output, not injection.
- **No per-request LLM deadline.** Every configured profile runs at `llm_timeout_ms` (15s
  default), so four profiles block a sync handler for up to 60s, with no cumulative cost
  ceiling.
- **`orchestrator.py:94`** appends to `session["history"]` with no trim; `conversation_id` is
  client-supplied, so both per-session and session-count growth are attacker-controlled.
- **Dead security flag.** `allow_legacy_anonymous_api` is parsed from the environment and
  never read; it advertises anonymous access that does not exist and that a future change
  could wrongly enable.
- **Cache keys are not user-scoped** (`response_cache.py`): `sha256(intent + message)` with a
  hit returning before output validation.
- **Absolute `sqlite_path` returned** in `/api/v1/stats` to analyst-and-above.
- **`tests/conftest.py` overrides pytest's builtin `tmp_path`** fixture, writing under
  `.pytest-fixtures`. Gitignored, so not a tracked-artefact defect, but shadowing a builtin
  breaks silently under `tmp_path_factory` or xdist.

## Other observations

- The **frontend is genuinely clean**: React 18.2 + Vite 8 + TS 5.2, real strict config
  (`strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`), a real
  flat ESLint config, typed API payloads, and **zero `any` occurrences** across all 21 source
  files. No secrets in client code.
- Repo hygiene is good: zero tracked build, cache, or temp artefacts; a working tree with
  nothing untracked; one authoritative `bun.lock` at the root and no nested lockfiles; no
  literal secret material anywhere in tracked files.
- `docs/` holds 130 files (42 md / 41 html / 44 json) for a small markdown corpus, and
  `docs:check` validates only the 12 files in `docs/current/`. Seven of those, plus
  `docs/README.md`, still document `pnpm`. Editing them invalidates their `sourceChecksum`
  with no generator available to refresh it — the trap that item 10 removed the false remedy
  for. `docs/release-manifest.json` also still records the old `docsBuild` command.
- Test suite: 472 tests, 15 files, with 12 duplicated test names and two near-clone files
  (`test_advanced.py` / `test_vigorous.py`). No coverage requirement. No network-dependent
  tests; the one live-LLM test is triple-gated, so CI is not flaky from missing keys.
- `test_round3.py::test_response_time_p95` is timing-sensitive (150 ms budget) and flaked once
  under concurrent load. It was isolated with a scoped `git stash` and passed both with and
  without the changes, so the flake is machine contention, not a regression.
- `dependabot.yml` declares the `npm` ecosystem for `frontend/` and `convex-adapter/`, which
  are Bun workspaces; whether those entries update the root `bun.lock` is unverified.
- `data/test_tmp/` holds ~80 MB of scratch that is never cleaned. It is correctly gitignored.
